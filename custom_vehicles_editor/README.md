# Редактор CustomVehicles

Кроссплатформенный визуальный редактор YAML-моделей и вариантов транспорта для плагина
CustomVehicles. Интерфейс работает на русском языке и сохраняет файлы непосредственно в формате,
который читает плагин — промежуточная конвертация не нужна.

## Возможности

- создание, открытие, сохранение, «Сохранить как» и экспорт `.yaml`/`.yml`;
- список недавних файлов с поддержкой пробелов, кириллицы и других Unicode-символов в путях;
- валидация перед записью с точным путём к ошибочному полю;
- атомарная запись через временный файл, синхронизацию и замену;
- режим визуальной модели и отдельный структурированный режим варианта транспорта;
- иерархия с упорядоченным Shift-мультивыделением, активной деталью и групповыми командами;
- добавление, дублирование, удаление, переименование, скрытие, блокировка и изменение порядка;
- поиск по полному сгенерированному каталогу из 1 060 блочных материалов Paper 1.21.1;
- числовой инспектор позиции, масштаба, Euler XYZ-вращения, hitbox и Display-настроек;
- один групповой gizmo перемещения/вращения и signed resize-ручки `±X/±Y/±Z`
  с настраиваемой привязкой;
- редакторские скрытие и блокировка, зеркальные копии по X и Z;
- application undo/redo из toolbar, native-меню и Cmd/Ctrl-сочетаний с группировкой
  непрерывного ввода и перетаскивания gizmo;
- перспективная и ортографическая камеры, стандартные виды, фокус и сброс;
- автоматический локальный vanilla-слой из установленного Minecraft Java Edition без
  распространения Mojang assets;
- ручные PNG-текстуры материалов и предпросмотр обычных Minecraft resource pack из папки или ZIP;
- приоритет, включение, пересканирование и диагностика ресурс-паков без изменения YAML;
- сетка, оси, начало координат, стрелка направления вперёд, hitbox и границы деталей.

## Требования

- Node.js `>=22.12.0`; для разработки рекомендуется актуальный Node.js 22 или 24;
- npm, входящий в поставку Node.js;
- macOS или Windows.

Установка и запуск:

```bash
npm install
npm run dev
```

При первом `npm run dev` штатная команда `install-electron` один раз скачивает
Electron runtime для текущей платформы, поэтому этому запуску нужен доступ в интернет.

Проверки:

```bash
npm run typecheck
npm run lint
npm run test
npm run build
```

## Работа с файлами

1. Нажмите **+ Модель** или **+ Вариант**.
2. Отредактируйте документ. Красная индикация в строке состояния блокирует сохранение и экспорт.
3. Для модели выберите **Экспорт** и укажите каталог
   `plugins/CustomVehicles/models/`. Для варианта укажите
   `plugins/CustomVehicles/vehicles/`.
4. На сервере выполните `/cv reload`.

Редактор также может напрямую открывать исходные встроенные модели из
`src/main/resources/models/` и варианты из `src/main/resources/vehicles/`.

Поддерживаются две схемы:

- модель: обязательные `schema-version`, `id`, `display-name` и `parts`; необязательные
  `coordinate-system` (по умолчанию `positive-z`), `interaction`, `display` (по умолчанию `2/1`)
  и редакторское `editor`;
- вариант: `schema-version`, `id`, `display-name`, `behavior`, одиночное `model` либо ролевое
  `models`, необязательные `item`, `menu-description` и `permission`.

`car` и `wagon` используют поле `model`. `train` использует роли `locomotive` и `wagon`,
а `tram` — `front`, `middle` и `rear`.

Метаданные `editor.hidden-parts` и `editor.locked-parts` сохраняются в YAML для удобства
редактирования. Плагин их безопасно игнорирует.

У детали обязательны `id`, блочный `material`, `position` и `scale`; `type` по умолчанию `block`,
а `rotation-degrees` — `(0, 0, 0)`. Модель содержит от 1 до 512 деталей. Координаты ограничены
диапазоном ±256, scale — `0.0001…64`, rotation — ±360000°. Размер файла не может превышать
1 048 576 UTF-8 байт. Если `item` варианта присутствует, его `material`, `name`, `lore` и
`custom-model-data` можно задавать независимо; незаданные значения выбираются плагином по
behavior и display-name.

## Координаты и преобразования

- начало модели — `(0, 0, 0)`;
- для обычной модели `+X` направлен вправо, `+Y` вверх, `+Z` вперёд;
- направление вперёд задаётся `coordinate-system.forward`: `positive-z` или `negative-z`;
- `position` обозначает центр кубоида;
- `scale` задаёт его полный размер в блоках относительно центрального pivot;
- `rotation-degrees` применяется в порядке Euler `XYZ` и переводится в quaternion;
- `interaction.offset` задаёт нижний центр (location/anchor) Bukkit Interaction; его область
  продолжается вверх на `height`, а не симметрично вокруг offset;
- зеркальная копия по X инвертирует позицию X и вращения Y/Z;
- зеркальная копия по Z инвертирует позицию Z и вращения X/Y.

### Мультивыделение и групповые команды

Обычный щелчок оставляет выбранной одну деталь. `Shift+щелчок` в иерархии или сцене добавляет
деталь либо удаляет её из выделения. Последняя добавленная деталь становится активной; если её
удалить из выделения, активной становится последняя из оставшихся. Обычный щелчок по пустому
месту очищает выделение, `Shift+щелчок` по пустому месту его сохраняет. Правая и средняя кнопки
мыши выделение не меняют.

Удаление, дублирование, зеркальная копия, материал, скрытие, блокировка и изменение порядка
выполняются для всего выделения одной операцией Undo. Заблокированные детали пропускаются всеми
групповыми командами, кроме самой блокировки/разблокировки; строка состояния сообщает их число.
Выделение является transient-состоянием редактора: само по себе оно не делает документ dirty и
не сериализуется, но Undo/Redo документа восстанавливает соответствующее выделение.

Перемещение применяет одинаковый delta ко всем незаблокированным выбранным деталям. Вращение
происходит вокруг центра их общей model-space bounding box. Временный pivot существует только в
сцене и не записывается в YAML. Для scale-режима используются отдельные ручки `+X/−X`,
`+Y/−Y`, `+Z/−Z`: противоположная грань детали или общей границы остаётся неподвижной, а
центральная `position` автоматически сдвигается. Для одной повёрнутой детали якорь вычисляется в
её локальном базисе. Для группы базис по умолчанию совпадает с осями модели.

Неравномерный общий scale повёрнутого кубоида может математически создать shear, которого нет в
YAML TRS-схеме. Для такой детали редактор явно применяет равномерный representable scale,
сохраняя форму и точные грани общей группы, и показывает сообщение в строке состояния.

Превью использует эти же соглашения. Глобальный yaw транспорта и наклон рельса добавляются
плагином через quaternion-композицию, а не через арифметическое сложение Euler-углов.
Bukkit Interaction остаётся выровненным по мировым осям даже когда транспорт наклонён на рельсе;
каркас hitbox в редакторе показывает его локальное положение при нулевой ориентации транспорта.
Режим `negative-z` выполняет настоящий разворот корня на 180° и поэтому также меняет знак
авторской оси X относительно осей поведения. Он сохранён для точной совместимости старой машины;
для новых моделей рекомендуется `positive-z`.

Подробнее об устройстве приложения: [docs/architecture.md](docs/architecture.md).

## Текстуры и ресурс-паки

Кнопка **Ресурсы…** открывает локальные настройки предпросмотра. Поддерживаются папки и `.zip`
обычного Minecraft resource pack. Порядок сверху вниз задаёт приоритет; пак можно выключить,
пересканировать, переместить, показать в Finder/Explorer или удалить из настроек. Переключатель
**Текстуры / Цвета материалов** оставляет прежний детерминированный цвет доступным в любой момент.

При первом запуске редактор ищет локальные client JAR Minecraft Java Edition:

- macOS: `~/Library/Application Support/minecraft/versions/`;
- Windows: `%APPDATA%/.minecraft/versions/`.

Версия определяется по launcher JSON, если он доступен; целевая `1.21.1` имеет приоритет.
Другие найденные версии можно переключать в менеджере. Для стороннего launcher доступны
**Найти автоматически** и **Выбрать Minecraft JAR**. Редактор ничего не скачивает из
неофициальных или официальных источников: используется только уже установленный либо явно
выбранный локальный client JAR.

Выбранный JAR образует нижний vanilla-слой. Индекс и разрешённые block resources извлекаются
только в `userData/resource-preview/cache`; исходный путь, размер, время изменения, версия и
SHA-256 участвуют в cache identity. Неизменённый JAR повторно не распаковывается. Если установка
перемещена или удалена, редактор показывает неблокирующую диагностику и оставляет цветовой
fallback.

В карточке выбранного Material можно назначить PNG сразу на все шесть граней, заменить его или
очистить. PNG декодируется main-процессом и копируется в управляемое хранилище Electron
`userData/resource-preview/manual`, поэтому перенос исходного файла не ломает назначение.
Настройки паков находятся в `userData/resource-preview/settings.json`, а безопасные индексы ZIP —
в `userData/resource-preview/cache`. Эти пути и настройки никогда не записываются в YAML;
поле детали остаётся, например, `material: ACACIA_PLANKS`.

Приоритет источников: ручное назначение → верхний включённый пак → нижние включённые паки →
локальные vanilla-ресурсы → детерминированный цвет. Поддерживаются стандартные `blockstates`,
parent-цепочки и texture
variables, common cube layouts (`cube_all`, `cube`, `cube_column`, `cube_bottom_top`,
`orientable`), а также детерминированный вариант и прямой `textures/block/<id>.png` fallback.
Сложная custom geometry по возможности приближается шестью гранями, иначе используется цвет с
диагностикой. Подробные границы поддержки: [docs/resource-pack-support.md](docs/resource-pack-support.md).

## Клавиатура и мышь

| Действие | Клавиши |
| --- | --- |
| Перемещение / вращение / масштаб | `W` / `E` / `R` |
| Добавить/убрать деталь из выделения | `Shift+ЛКМ` |
| Дублировать выделение | `Cmd/Ctrl+D` |
| Удалить выделение | `Delete` или `Backspace` |
| Отменить / повторить | macOS: `Cmd+Z` / `Cmd+Shift+Z`; Windows/Linux: `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` |
| Сохранить / сохранить как | `Cmd/Ctrl+S`, `Cmd/Ctrl+Shift+S` |

Глобальные клавиши деталей и gizmo не срабатывают при вводе в `input`, `textarea` или `select`
и при открытом окне настроек ресурс-паков.
В сцене левая кнопка выбирает деталь и вращает камеру, `Shift+ЛКМ` меняет мультивыделение,
правая кнопка панорамирует, колесо масштабирует. Камера отключается только во время активного
перетаскивания transform/resize-ручки. Resize-ручки используют увеличенную screen-space область
захвата и продолжают жест за пределами canvas. Финальные координаты `pointerup` синхронно
пересчитывают authoritative transform map, который напрямую записывается в модель без чтения
scene matrices и ожидания следующего кадра. На macOS meaningful resize, завершившийся
`lostpointercapture` без window-`pointerup`, commit-ит тот же последний рассчитанный snapshot;
потеря capture без движения остаётся отменой. Поэтому быстрый release даёт тот же результат, что
и медленный drag к той же точке; `Esc`, `pointercancel` или blur безопасно отменяют изменение и
сразу возвращают управление камерой.

## Сборка приложений

```bash
npm run dist
npm run dist:mac
npm run dist:win
```

- `dist:mac` создаёт unsigned `.dmg` и `.zip` для macOS arm64;
- `dist:win` создаёт NSIS installer и portable `.exe` для Windows x64;
- артефакты попадают в `release/`.

Без подписи macOS может показать предупреждение Gatekeeper. Для локальной доверенной сборки
откройте приложение через контекстное меню **Открыть**. Windows SmartScreen также может запросить
подтверждение запуска неподписанного приложения.

Локально исходники, TypeScript, тесты, production renderer, sandbox preload и упакованное
приложение проверены на macOS arm64; unsigned DMG и ZIP успешно созданы. Создание
Windows-артефакта локально не заявляется — его следует выполнять на Windows или в CI.

## Безопасность

Renderer не имеет доступа к Node.js. Окно использует `contextIsolation`, sandbox и включённую
web security; разрешения браузера отклоняются. Preload публикует только узкий типизированный API.
Чтение доступно лишь через системный диалог или список недавних файлов, запись — только в путь,
явно выбранный пользователем. Внешняя навигация и создание окон запрещены.

Ресурс-паки и пользовательский Minecraft JAR выбираются только системным диалогом. ZIP/JAR не
исполняются: scanner отклоняет
абсолютные/обходные пути, ссылки и чрезмерные размеры, копирует только allowlist
`pack.mcmeta`/`assets/*/{blockstates,models,textures}` в управляемый cache и выдаёт renderer
только opaque asset token. Вся обработка локальна и офлайн после выбора файлов. Приложение не
содержит, не коммитит и не распространяет текстуры Mojang; cache из `userData` не попадает в
ASAR, DMG, ZIP или Windows-сборки.

## Обновление списка материалов

`src/shared/block-materials.json` генерируется из `BlockTypeKeys` и `Material` Paper 1.21.1 и
хранится в репозитории, поэтому Java не нужен для запуска редактора. При переходе плагина на
другую версию Paper повторно запустите `./gradlew generateBlockMaterials` в проекте плагина и
закоммитьте обновлённый JSON. CI повторяет генерацию и проверяет, что файл не устарел. Ручное
редактирование неполного списка не рекомендуется.
