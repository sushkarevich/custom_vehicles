# Редактор CustomVehicles

Кроссплатформенный визуальный редактор YAML-моделей и вариантов транспорта для плагина
CustomVehicles. Интерфейс работает на русском языке и сохраняет файлы непосредственно в формате,
который читает плагин — промежуточная конвертация не нужна.

## Возможности

- создание, открытие, сохранение, «Сохранить как» и экспорт `.yaml`/`.yml`;
- список недавних файлов с поддержкой пробелов, кириллицы и других Unicode-символов в путях;
- валидация перед записью с точным путём к ошибочному полю;
- атомарная запись через временный файл, синхронизацию и замену;
- режим визуальной модели и отдельный структурированный режим варианта транспорта;
- иерархия деталей, добавление, дублирование, удаление, переименование и изменение порядка;
- поиск по полному сгенерированному каталогу из 1 060 блочных материалов Paper 1.21.1;
- числовой инспектор позиции, масштаба, Euler XYZ-вращения, hitbox и Display-настроек;
- gizmo перемещения, вращения и масштаба с настраиваемой привязкой;
- редакторские скрытие и блокировка, зеркальные копии по X и Z;
- undo/redo с группировкой непрерывного ввода и перетаскивания gizmo;
- перспективная и ортографическая камеры, стандартные виды, фокус и сброс;
- сетка, оси, начало координат, стрелка направления вперёд, hitbox и границы деталей.

## Требования

- Node.js `>=22.12.0`; для разработки рекомендуется актуальный Node.js 22 или 24;
- npm, входящий в поставку Node.js;
- macOS или Windows.

Установка и запуск:

```bash
npm install
npm run dev
```

При первом `npm run dev` штатная команда `install-electron` один раз скачивает
Electron runtime для текущей платформы, поэтому этому запуску нужен доступ в интернет.

Проверки:

```bash
npm run typecheck
npm run lint
npm run test
npm run build
```

## Работа с файлами

1. Нажмите **+ Модель** или **+ Вариант**.
2. Отредактируйте документ. Красная индикация в строке состояния блокирует сохранение и экспорт.
3. Для модели выберите **Экспорт** и укажите каталог
   `plugins/CustomVehicles/models/`. Для варианта укажите
   `plugins/CustomVehicles/vehicles/`.
4. На сервере выполните `/cv reload`.

Редактор также может напрямую открывать исходные встроенные модели из
`src/main/resources/models/` и варианты из `src/main/resources/vehicles/`.

Поддерживаются две схемы:

- модель: обязательные `schema-version`, `id`, `display-name` и `parts`; необязательные
  `coordinate-system` (по умолчанию `positive-z`), `interaction`, `display` (по умолчанию `2/1`)
  и редакторское `editor`;
- вариант: `schema-version`, `id`, `display-name`, `behavior`, одиночное `model` либо ролевое
  `models`, необязательные `item`, `menu-description` и `permission`.

`car` и `wagon` используют поле `model`. `train` использует роли `locomotive` и `wagon`,
а `tram` — `front`, `middle` и `rear`.

Метаданные `editor.hidden-parts` и `editor.locked-parts` сохраняются в YAML для удобства
редактирования. Плагин их безопасно игнорирует.

У детали обязательны `id`, блочный `material`, `position` и `scale`; `type` по умолчанию `block`,
а `rotation-degrees` — `(0, 0, 0)`. Модель содержит от 1 до 512 деталей. Координаты ограничены
диапазоном ±256, scale — `0.0001…64`, rotation — ±360000°. Размер файла не может превышать
1 048 576 UTF-8 байт. Если `item` варианта присутствует, его `material`, `name`, `lore` и
`custom-model-data` можно задавать независимо; незаданные значения выбираются плагином по
behavior и display-name.

## Координаты и преобразования

- начало модели — `(0, 0, 0)`;
- для обычной модели `+X` направлен вправо, `+Y` вверх, `+Z` вперёд;
- направление вперёд задаётся `coordinate-system.forward`: `positive-z` или `negative-z`;
- `position` обозначает центр кубоида;
- `scale` задаёт его полный размер в блоках относительно центрального pivot;
- `rotation-degrees` применяется в порядке Euler `XYZ` и переводится в quaternion;
- `interaction.offset` задаёт нижний центр (location/anchor) Bukkit Interaction; его область
  продолжается вверх на `height`, а не симметрично вокруг offset;
- зеркальная копия по X инвертирует позицию X и вращения Y/Z;
- зеркальная копия по Z инвертирует позицию Z и вращения X/Y.

Превью использует эти же соглашения. Глобальный yaw транспорта и наклон рельса добавляются
плагином через quaternion-композицию, а не через арифметическое сложение Euler-углов.
Bukkit Interaction остаётся выровненным по мировым осям даже когда транспорт наклонён на рельсе;
каркас hitbox в редакторе показывает его локальное положение при нулевой ориентации транспорта.
Режим `negative-z` выполняет настоящий разворот корня на 180° и поэтому также меняет знак
авторской оси X относительно осей поведения. Он сохранён для точной совместимости старой машины;
для новых моделей рекомендуется `positive-z`.

Подробнее об устройстве приложения: [docs/architecture.md](docs/architecture.md).

## Клавиатура и мышь

| Действие | Клавиши |
| --- | --- |
| Перемещение / вращение / масштаб | `W` / `E` / `R` |
| Дублировать деталь | `Cmd/Ctrl+D` |
| Удалить деталь | `Delete` или `Backspace` |
| Отменить / повторить | `Cmd/Ctrl+Z`, `Cmd/Ctrl+Shift+Z` или `Cmd/Ctrl+Y` |
| Сохранить / сохранить как | `Cmd/Ctrl+S`, `Cmd/Ctrl+Shift+S` |

Глобальные клавиши деталей и gizmo не срабатывают при вводе в `input`, `textarea` или `select`.
В сцене левая кнопка выбирает деталь и вращает камеру, правая кнопка панорамирует, колесо
масштабирует.

## Сборка приложений

```bash
npm run dist
npm run dist:mac
npm run dist:win
```

- `dist:mac` создаёт unsigned `.dmg` и `.zip` для macOS arm64;
- `dist:win` создаёт NSIS installer и portable `.exe` для Windows x64;
- артефакты попадают в `release/`.

Без подписи macOS может показать предупреждение Gatekeeper. Для локальной доверенной сборки
откройте приложение через контекстное меню **Открыть**. Windows SmartScreen также может запросить
подтверждение запуска неподписанного приложения.

Локально исходники, TypeScript, тесты, production renderer, sandbox preload и упакованное
приложение проверены на macOS arm64; unsigned DMG и ZIP успешно созданы. Создание
Windows-артефакта локально не заявляется — его следует выполнять на Windows или в CI.

## Безопасность

Renderer не имеет доступа к Node.js. Окно использует `contextIsolation`, sandbox и включённую
web security; разрешения браузера отклоняются. Preload публикует только узкий типизированный API.
Чтение доступно лишь через системный диалог или список недавних файлов, запись — только в путь,
явно выбранный пользователем. Внешняя навигация и создание окон запрещены.

## Обновление списка материалов

`src/shared/block-materials.json` генерируется из `BlockTypeKeys` и `Material` Paper 1.21.1 и
хранится в репозитории, поэтому Java не нужен для запуска редактора. При переходе плагина на
другую версию Paper повторно запустите `./gradlew generateBlockMaterials` в проекте плагина и
закоммитьте обновлённый JSON. CI повторяет генерацию и проверяет, что файл не устарел. Ручное
редактирование неполного списка не рекомендуется.
